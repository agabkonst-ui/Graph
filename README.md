# Graph — вариант 1, этап 1

CLI-прототип инструмента визуализации зависимостей пакетов Alpine Linux
(apk). Читает семь параметров из XML, проверяет их и выводит в формате
`ключ=значение`. Используется только стандартная библиотека Python 3.10+.
Сборка и установка дополнительных библиотек не требуются.

Получение зависимостей, анализ и визуализация относятся к следующим этапам.
На этапе 1 сетевых запросов нет, изображение не создаётся.

## Быстрый запуск

Откройте PowerShell в корне проекта:

```powershell
.\run.bat
.\test.bat
.\demo.bat
```

Скрипты используют `py -3`. Если Python не найден, перед запуском укажите
интерпретатор, например из предыдущей работы:

```powershell
$env:PYTHON_EXE = "C:/Emulator/Python/Python313/python.exe"
```

Если доступна команда `python`, можно задать `$env:PYTHON_EXE = "python"`.
Сам интерпретатор в репозиторий копировать не нужно.

Для Linux/macOS:

```sh
sh run.sh
sh test.sh
sh demo.sh
```

Можно задать переменную `PYTHON_EXE` с путём к своему Python.

## Настройки

Все пользовательские параметры анализа задаются только в XML.
Опция CLI `--config FILE` выбирает XML-файл. Без опции загружается
`config/default.xml` из папки проекта.

```powershell
.\run.bat --config config/default.xml
.\run.bat --config config/remote.xml
.\run.bat --help
```

Пример XML:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
  <package_name>A</package_name>
  <repository>../examples/test_repository.txt</repository>
  <test_mode>true</test_mode>
  <package_version>1.0</package_version>
  <output_file>../graph.svg</output_file>
  <max_depth>3</max_depth>
  <filter_substring>SKIP</filter_substring>
</config>
```

Ожидаемый вывод:

```text
package_name=A
repository=../examples/test_repository.txt
test_mode=true
package_version=1.0
output_file=../graph.svg
max_depth=3
filter_substring=SKIP
```

| Параметр | Смысл и правила |
| --- | --- |
| `package_name` | Имя пакета: большие латинские буквы в тестовом режиме |
| `repository` | Путь к читаемому файлу при `true`, HTTP(S) URL при `false` |
| `test_mode` | `true` или `false`, регистр не важен |
| `package_version` | Непустой идентификатор версии без пробелов и слешей |
| `output_file` | Имя будущего SVG-файла в существующем каталоге |
| `max_depth` | Целое неотрицательное число, 0 означает корневой пакет |
| `filter_substring` | Подстрока имени; пустая строка отключает фильтр |

Все семь тегов обязательны. Пустой фильтр задаётся как
`<filter_substring />`. Пробелы по краям значений удаляются.
Относительные пути считаются от каталога XML, а не текущей папки терминала.
В выводе сохраняется исходная запись пути.

В обычном режиме имя начинается со строчной латинской буквы или цифры,
дальше разрешены строчная латиница, цифры и `+_.-`. В тестовом режиме
принимаются `A`, `B`, `ABC` и другие последовательности больших букв A–Z.

Версия начинается с латинской буквы или цифры; далее разрешены латиница,
цифры и `._+~:-`, например `1.36.1-r1`. На этом этапе проверяется базовый
синтаксис, а существование пакета и версии будет проверяться на этапе 2.

Фильтр содержит латиницу, цифры или `+_.-`. Это обычная подстрока,
а не регулярное выражение. Само исключение пакетов относится к этапу 3.

Для URL проверяются HTTP(S), наличие сервера, допустимый порт и отсутствие
пробелов. Данные авторизации и фрагмент `#...` не поддерживаются.
Доступность сервера не проверяется. В `config/remote.xml` указан пример
на `example.org`, а не действующий репозиторий Alpine.

В локальном режиме файл открывается для проверки доступности чтения.
Текстовый пример `examples/test_repository.txt` подготовлен для будущего
анализа графа; его содержимое на этапе 1 ещё не разбирается.

Для изображения проверяются расширение `.svg`, допустимость имени,
существование родительского каталога и отсутствие каталога вместо файла.
Зарезервированные имена Windows вроде `CON.svg` отклоняются.
Файл не создаётся и не перезаписывается. Проверка фактической записи
относится к будущему этапу визуализации.

## Проверка и обработка ошибок

`test.bat` запускает 38 тестов с множеством подтестов. Ожидается:

```text
Ran 38 tests
OK
```

`demo.bat` выполняет 19 сценариев: два успешных режима, неверное значение
и отсутствие каждого из семи параметров, отсутствующий XML, повреждённый
XML и неверная схема URL. Временные XML создаются в системном временном
каталоге и удаляются. В поставке ничего не изменяется.

В демонстрации сообщения «Ошибка конфигурации» ожидаемы. Для каждого
сценария сравниваются фактический и ожидаемый коды завершения.
В конце должно появиться:

```text
Все демонстрационные проверки завершены успешно.
```

Для ручной проверки замените в копии XML глубину на `-1` и запустите
через `--config`: программа должна назвать параметр `max_depth` и вернуть 2.
Для нескольких независимых неверных значений выводятся все их ошибки.

Обрабатываются неизвестные и повторяющиеся теги, отсутствующие параметры,
атрибуты, вложенные теги, посторонний текст, повреждённый XML и ошибки чтения.

| Код завершения | Результат |
| --- | --- |
| `0` | Успешный запуск или справка |
| `2` | Ошибка конфигурации либо аргументов CLI |

Обычный запуск печатает параметры в stdout, ошибки в stderr.
Демонстрация направляет оба потока на экран в порядке сценариев.

Прямой запуск в PowerShell без оболочек:

```powershell
$env:PYTHONPATH = "src"
python -B -m graph_tool --config config/default.xml
python -B -m unittest discover -s tests -v
```

В Linux/macOS:

```sh
PYTHONPATH=src python3 -B -m graph_tool --config config/default.xml
PYTHONPATH=src python3 -B -m unittest discover -s tests -v
```

## Структура и функции

| Файл | Назначение |
| --- | --- |
| `src/graph_tool/cli.py` | `main`, `create_parser`: запуск и коды завершения |
| `src/graph_tool/xml_config.py` | `load_config`, чтение XML и проверка схемы |
| `src/graph_tool/validation.py` | `validate_config`: согласование и сбор ошибок |
| `src/graph_tool/scalars.py` | Парсеры семи пользовательских значений |
| `src/graph_tool/locations.py` | Проверка URL, локального пути и SVG-имени |
| `src/graph_tool/model.py` | `Config`, `format_config`: модель и вывод |
| `src/graph_tool/errors.py` | `ConfigError`: ошибка конфигурации |
| `config/` | XML-примеры обоих режимов |
| `examples/` | Текстовые тестовые данные |
| `tests/` | Автоматические проверки |
| `scripts/demo.py` | Демонстрация ошибок и успешных запусков |
| `CHECKLIST.md` | Проверка требований этапа и оформления |
| `SUBMISSION.md` | Загрузка в Graph и текст коммита |

Модули, классы и функции снабжены docstring в исходниках.
