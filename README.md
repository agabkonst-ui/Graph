# Анализатор зависимостей Alpine Linux

Конфигурационное управление. Вариант 1, этап 4 «Дополнительные операции».
Программа строит граф зависимостей и находит пакеты, зависящие от заданного.
В обычном режиме она читает индекс репозитория Alpine Linux по URL, в тестовом
режиме — текстовое описание графа. Используется стандартная библиотека Python.

## Запуск

Нужен Python 3.10 или новее. Команды выполняются из корня репозитория.
Установка библиотек и сборка не требуются.

| Действие | Windows PowerShell | Linux / macOS |
| --- | --- | --- |
| Сетевой режим с настройками из корневого XML | `.\run.bat` | `sh run.sh` |
| Граф из локального файла | `.\run.bat config/default.xml` | `sh run.sh config/default.xml` |
| Прямые зависимости, вывод этапа 2 | `.\run.bat --direct` | `sh run.sh --direct` |
| Обратные зависимости, этап 4 | `.\run.bat --reverse` | `sh run.sh --reverse` |
| Автотесты без интернета | `.\test.bat` | `sh test.sh` |

В Windows скрипты запуска, тестов и демонстрации принимают путь к Python
через переменную `PYTHON_EXE`. Например, если в терминале доступен `python`:

```powershell
$env:PYTHON_EXE = (Get-Command python).Source
.\test.bat
```

Для показа этапа 1 запустите `.\demo.bat` (Linux/macOS: `sh demo.sh`).
Демонстрация выводит параметры XML и показывает ошибки по каждому полю.

При ошибке конфигурации, файла или загрузки программа печатает сообщение
в stderr и возвращает код 1.

## Настройки XML

Корневой элемент — `<config>`. Каждый из семи параметров указывается один раз.

| Параметр | Значение |
| --- | --- |
| `package_name` | Исходный пакет. Для тестового графа используются имена из латинских букв A–Z. |
| `repository` | URL каталога Alpine для одной архитектуры, URL `APKINDEX.tar.gz` или путь к тестовому файлу. |
| `test_mode` | `true` для локального файла, `false` для сетевого репозитория. |
| `package_version` | Точная версия исходного APK. В тестовом графе версии отсутствуют, но поле обязательно. |
| `output_file` | Имя SVG-файла для этапа 5. На этапе 3 граф выводится в консоль. |
| `max_depth` | Целое число от 0. У исходного пакета глубина 0. |
| `filter_substring` | Подстрока имени пакета с учётом регистра. Пустое поле отключает фильтр. |

Относительный путь к тестовому файлу отсчитывается от каталога XML.
Формат тестового файла — `A: B C`, где у A две прямые зависимости.
Строка `D:` объявляет пакет без зависимостей. Пустые строки пропускаются.
Пакет, упомянутый только справа, считается листом.

## Построение графа

BFS использует очередь и запоминает глубину первого посещения каждого пакета.
При повторной встрече пакет не ставится в очередь ещё раз, но ребро сохраняется.
Так циклы остаются видимыми, а общая зависимость выводится одной строкой.
На границе `max_depth` вершина попадает в граф, а её рёбра не читаются.
При `max_depth=0` граф состоит из исходного пакета.

Фильтр исключает совпавший пакет и его рёбра. Узлы за ним остаются в графе,
если к ним ведёт другой разрешённый путь. Если совпал исходный пакет,
программа выводит сообщение о пустом графе.

В сетевом режиме программа один раз загружает `APKINDEX.tar.gz`, ищет
исходный пакет по имени и точной версии и разбирает поля зависимостей
и предоставляемых имён. Если исходной версии нет в индексе, программа
пробует прочитать метаданные файла `<имя>-<версия>.apk`.

Для каждой зависимости программа выбирает первый подходящий пакет
в индексе по имени и ограничению версии. При отсутствии подходящего пакета
с таким именем она проверяет поставщиков виртуального имени (`so:`, `cmd:`,
`pc:` и другие). Анализ ограничен настроенным репозиторием. Пометка `(?)`
означает, что подходящий пакет в нём не найден. Конфликты с префиксом `!`
пропускаются. [Формат APK][apk-metadata] и [ограничения версий][apk-world].

## Примеры для демонстрации

Без фильтра видны две дороги к D, цикл D → A и ветка SKIP → HIDDEN.

```powershell
.\run.bat config/stage3-cycle.xml
```

```text
Граф зависимостей (BFS):
[0] A -> B, C
[1] B -> D
[1] C -> D, SKIP
[2] D -> A
[2] SKIP -> HIDDEN
[3] HIDDEN -> —
```

С фильтром `SKIP` из результата исчезают SKIP и доступный только через него
HIDDEN. Рёбра B → D, C → D и D → A сохраняются.

```powershell
.\run.bat config/default.xml
```

При `max_depth=1` программа выводит A, B и C.

```powershell
.\run.bat config/stage3-depth.xml
```

Режим этапа 2 читает тестовый APKINDEX и печатает зависимости построчно.

```powershell
.\run.bat --direct tests/fixtures/config.xml
```

## Обратные зависимости

Если A зависит от B, то A — прямая обратная зависимость B. Если C зависит
от A, то C — транзитивная обратная зависимость B. В режиме `--reverse`
программа собирает входящие рёбра из всего указанного репозитория
и запускает по ним тот же BFS без рекурсии. Число в квадратных скобках —
минимальная глубина. Выбранный пакет исключён из списка даже при цикле,
а каждая его обратная зависимость выводится один раз.

`max_depth` ограничивает обратный обход. При глубине 0 список пуст.
Фильтр удаляет совпадающие пакеты и их рёбра перед обходом. Для Alpine
используется один APKINDEX и те же правила выбора версии и поставщика,
что при прямом обходе. `--reverse` и `--direct` взаимоисключающие.

Примеры используют один локальный файл репозитория:

| Команда в PowerShell | Ожидаемый результат |
| --- | --- |
| `.\run.bat --reverse config/stage3-cycle.xml` | `[1] D`, `[2] B`, `[2] C`; цикл не возвращает A в список |
| `.\run.bat --reverse config/stage3-depth.xml` | Только `[1] D` при глубине 1 |
| `.\run.bat --reverse config/stage4-transitive.xml` | Для HIDDEN: `[1] SKIP`, `[2] C`, `[3] A` |
| `.\run.bat --reverse config/stage4-filter.xml` | Список пуст, поскольку фильтр исключает SKIP |

В Linux/macOS замените `.\run.bat` на `sh run.sh`; аргументы те же.

## Исходный код

- `src/main.py` читает аргументы и запускает выбранный режим.
- `src/config.py` загружает и проверяет семь настроек XML.
- `src/apk.py` загружает индекс или APK и читает поля метаданных.
- `src/apk_graph.py` выбирает точную исходную версию и сопоставляет зависимости
  с пакетами из индекса. `src/apk_versions.py` сравнивает версии.
- `src/local_graph.py` читает текстовое описание тестового графа.
- `src/dependency_graph.py` строит индекс обратных рёбер, выполняет BFS
  и выводит граф или список обратных зависимостей.
- `tests` содержит проверки CLI, конфигурации, обхода и чтения метаданных,
  включая подмену HTTP-ответов.
