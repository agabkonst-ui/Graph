# Как добавить этап 1 в Graph

1. В GitHub Desktop выберите Graph → Show in Explorer.
2. Скопируйте содержимое Graph-stage1 в открывшуюся папку репозитория,
   включая .gitignore и .gitattributes. Существующую папку .git сохраните.
3. Не создавайте лишний уровень Graph-stage1 внутри репозитория.
4. Выполните test.bat и demo.bat; при необходимости задайте PYTHON_EXE
   по инструкции README. В тестах должно быть OK.
5. Вернитесь в Desktop и проверьте список Changes. В нём не должно быть
   Python, PDF, архивов, скриншотов, кэшей и настроек редактора.
6. Заполните Summary, нажмите Commit to main, затем Push origin.
7. На сайте Graph проверьте появление файлов, коммита и статус Public.

Сообщение коммита — поле Summary:

```text
feat(config): добавить XML-конфигурацию
```

Необязательное поле Description:

```text
Вариант 1, этап 1: минимальный CLI-прототип инструмента зависимостей.
Добавить чтение семи параметров из XML и вывод в формате ключ-значение.
Проверять параметры, структуру XML, URL и локальные пути.
Добавить тесты и демонстрацию обработки ошибок.
```

Это Conventional/Scoped Commit: feat — новая функциональность,
config — область изменения. Не используйте Add files via upload.

Если Graph уже содержит автоматический Initial commit, он сам не
соответствует Conventional Commits. Поставка не меняет существующую историю:
её оформление нужно проверить отдельно перед сдачей.

Для загрузки через сайт: Add file → Upload files, перетащите содержимое
Graph-stage1 в корень репозитория и используйте это же сообщение коммита.
Файлы новой работы относятся к Graph; репозиторий Emulator сохраните отдельно.

Текст для сдачи преподавателю; замените последнюю строку реальной ссылкой:

```text
Практическая работа №2, вариант 1, этап 1.
Реализовано CLI-приложение с XML-конфигурацией семи параметров.
Параметры выводятся в формате ключ-значение.
Добавлена проверка всех параметров и демонстрация обработки ошибок.
Тесты: test.bat. Демонстрация: demo.bat. Инструкции: README.md.
Репозиторий: ВСТАВЬТЕ_ССЫЛКУ
```
